# 当前限制

这些限制是 Alpha 的明确边界，不应在宣传或交付中被弱化。

## 产品范围

- 当前只内置有限的中文政企方案契约、crosswalk 和 section specs，不是任意文种、任意文档的通用系统。
- 没有 Web UI、长期运行服务、多租户、账号权限或团队审批界面。
- 项目库是本地文件系统工作流，不是完整的企业知识库或文档管理系统。

## 材料理解与检索

- PDF 仅处理可提取文本；扫描件没有 OCR。
- 表格、图片、版式关系和附件语义不能完整保留。
- embedding 和候选召回会影响最终发现率；固定 gate 不能补回根本没有召回的证据。
- `--fake-embedder` 只验证流程，不可用于质量判断。
- prompt-injection 扫描是模式匹配，可能漏报，也不保证外部 Agent 不受材料文字影响。

## 生成与审计

- Runtime 不含生成式模型，不自动撰写业务正文。
- 句级切分不是语义 atomic-claim extraction；claim 和支持等级由 auditor 提交。
- 确定性检查能发现伪造引用、内容不一致、辖区错误、漏审和旧报告，但不能替代专业人员的业务判断。
- 最终文档质量仍受 writer、模板、输入材料与人工审阅影响。

## 安全与授权

- 材料、索引和运行工件默认以明文落盘；系统不提供存储加密和访问控制。
- 使用远端 embedding 或云端 Agent 会把材料内容发送给相应服务。
- 默认 integrity 模式不是身份授权；拥有整个工作区写权限的主体可以协调修改全部工件。
- signed 模式只有接口方向，尚未实现。
- 渲染门不重新读取源材料；审计后只替换源文件而保持 AuditBrief/audit map 不变，不会被渲染阶段单独发现。

## 评估

- 合成 demo 证明的是状态机和交付门行为，不是检索准确率。
- 仓库中的公开 benchmark 只覆盖检索子系统，不能推出整套方案生成质量。
- 现有评估规模不足以支持“通用可靠”“自动防幻觉”或“生产级准确率”等宣传。

## 兼容性

- 支持 Python 3.11 与 3.12；词法通道和精确定位依赖系统安装的 `ripgrep`。
- 文档模板与中文契约字段会被运行时消费，随意翻译或改名可能改变行为。
- Alpha 期间结构化 JSON 协议仍可能在明确迁移说明下调整。
